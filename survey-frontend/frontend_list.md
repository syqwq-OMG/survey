太棒了！抛弃简陋的原生 HTML，换上现代化的 Vue 3 框架，这个项目不仅颜值会发生质的飞跃，代码的工程化水平也能拉满。

其实前端的可视化问卷搭建，本质上就是在图形界面上构建一棵抽象语法树 (AST)；而问卷填写时的跳转逻辑，完全可以看作是一个有限状态自动机 (DFA) 的状态流转。理清了这些底层逻辑，用 Vue 的响应式数据来做数据绑定就会非常顺手。在数据统计模块，把收集到的原始数据清洗并用 ECharts 渲染出直观的 Dashboard，也正好契合数据科学处理与可视化的标准流程。

我们要分担前后端分离的架构，后端依然跑在你的 Fedora 物理机或本地环境中提供 API，前端用 Vite 独立起一个服务。

下面是为你量身定制的前端 Vue 3 大作业重构任务清单，我们将分五步走：

### 一、 前端基础设施搭建 (环境与依赖)
这一步是打地基，引入我们要用到的“神兵利器”。
* **初始化项目**：使用 Vite 创建 Vue 3 项目 (`npm create vite@latest`)。
* **安装核心依赖库**：
  * `element-plus` 及 `@element-plus/icons-vue`：搞定所有表单、按钮、弹窗的 UI。
  * `vue-router`：管理单页面应用 (SPA) 的路由跳转。
  * `axios`：处理 HTTP 请求，方便配置全局的 Token 拦截器。
  * `echarts`：用于实现漂亮的数据统计 Dashboard。
* **配置 Axios 拦截器**：写一个通用的请求封装，每次发请求自动从 `localStorage` 读取 Token 并塞入 Header，遇到 401 错误自动跳转回登录页。

### 二、 认证与基础页面 (Auth & Layout)
[cite_start]实现项目文档要求的用户注册和登录闭环 [cite: 171-182]。
* **配置路由表 (`router/index.js`)**：划分出 `/login`, `/dashboard`, `/builder`, `/survey/:id` 等核心路径。
* **开发 `Login.vue` 组件**：
  * 利用 Element Plus 的 `el-tabs` 或翻转卡片，把“登录”和“注册”做在同一个页面里。
  * 绑定表单校验规则（用户名长度、密码长度）。
  * 对接后端的 `/api/auth/register` 和 `/api/auth/login`。
* **开发 `Layout.vue` 骨架**：做一个包含顶部导航栏（显示当前用户名、退出登录按钮）的基础布局组件，供后台管理页面复用。

### 三、 核心难点 1：可视化问卷搭建 (Survey Builder)
[cite_start]这是替代手写 JSON 的关键，也是项目的一大亮点。你需要实现问卷信息的完整创建 [cite: 184-255]。
* **数据结构设计**：在 Vue 组件的 `ref` 或 `reactive` 中定义一个响应式的数组，专门用来存放题目数据。
* **开发“题目加工厂”界面**：
  * 提供“添加单选题”、“添加多选题”、“添加填空题”的按钮。
  * 点击按钮时，向数组中 `push` 对应题型的默认对象结构。
* **开发动态属性面板**：
  * 使用 `v-for` 渲染题目列表。
  * [cite_start]每道题内部提供 `el-input` 修改题干，提供动态列表增删选项 [cite: 211]。
  * [cite_start]为多选题配置“最少/最多选择”的数字输入框 [cite: 224-226]。
  * [cite_start]配置必答开关 (`is_required`) [cite: 212]。
* [cite_start]**开发跳转逻辑配置区**：允许用户选择“如果本题等于X，则跳转到题目Y” [cite: 246-253]。
* **提交动作**：点击保存时，直接将这棵组装好的“数据树”发送给 `POST /api/surveys`。

### 四、 核心难点 2：问卷动态渲染与跳转解析 (Survey Fill)
[cite_start]这是给普通填写者看的对外页面，需要根据问卷规则严格限制用户行为 [cite: 257-263]。
* **动态渲染引擎**：根据 URL 中的 ID 请求后端问卷详情，用 `v-for` 和 `v-if` 根据 `type` 渲染出不同的输入控件（单选框、复选框、输入框）。
* **前端校验防线**：在提交前，利用 Vue 遍历用户的答案，检查是否为空、多选数量是否达标、数字是否越界。这相当于在触发后端 400 报错前，先用前端给用户友好的提示。
* **跳转逻辑执行器 (Watch 监听)**：
  * 监听用户当前答题状态字典。
  * 一旦选项发生变化，评估 `jump_logic` 数组。如果触发条件，动态计算出被跳过的题目 ID，并通过 CSS 或 `v-show` 将其隐藏。

### 五、 数据看板与导出 (Dashboard & ECharts)
[cite_start]满足文档要求的统计与展示功能 [cite: 269-282]。
* **开发问卷列表页 (`Dashboard.vue`)**：用 `el-table` 展示当前用户创建的问卷，提供“发布/关闭”、“查看链接”、“查看统计”的按钮接口。
* **集成 ECharts 绘制图表**：
  * 对接 `GET /api/surveys/{id}/stats`。
  * [cite_start]将单选/多选的 `option_counts` 数据转换成 ECharts 需要的 `name` 和 `value` 格式，渲染成饼图或柱状图 [cite: 271-275]。
  * [cite_start]将数字填空题的 `average` 用显著的卡片指标展示 [cite: 278]。
* **JSON 导出功能**：实现一个简单的下载函数，将后端的统计 JSON 转换为 Blob 对象，触发浏览器下载。
